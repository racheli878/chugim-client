# חוגים — צד לקוח

ממשק בעברית (מימין לשמאל) למערכת ההרשמה לחוגים. משתתפות בוחרות חוג, רואות כמה מקומות נשארו ונרשמות. המנהלת מנהלת חוגים וקטגוריות.
השרת נמצא ב-repo נפרד: **Chugim** (ASP.NET Core 8 Web API).

**טכנולוגיות:** React 18, ‏Vite 5, ‏React Router 6, ‏JavaScript ו-CSS ידני עם משתני עיצוב. אין ספריית UI ואין ספריות נוספות.

## הרצה מקומית

דרישות: Node.js 18 ומעלה, והשרת רץ (ברירת מחדל `https://localhost:7180`).

```bash
copy .env.example .env.development   # Windows (ב-Mac/Linux: cp)
npm install
npm run dev                          # http://localhost:5173
```

| משתנה | תפקיד |
|---|---|
| `VITE_API_URL` | כתובת השרת, בלי `/` בסוף. נקראת בזמן הבנייה. |

בשרת הכתובת של הלקוח צריכה להיות מורשית ב-CORS (`Cors:AllowedOrigins`). בפיתוח `http://localhost:5173` כבר מוגדרת.

## מה יש באתר

כל האתר זמין רק אחרי כניסה, חוץ ממסכי הכניסה וההרשמה. השרת אוכף את אותו כלל.

| כתובת | מי | מה |
|---|---|---|
| `/login`, `/register` | אורחת | כניסה ופתיחת חשבון, עם בדיקות בצד הלקוח ושגיאות מהשרת ליד השדה המתאים |
| `/courses` | כולן | חוגים עם חיפוש, קטגוריה, "רק עם מקום", מיון ועימוד מהשרת. הסינון נשמר בכתובת |
| `/my` | משתתפת / מנהלת | משתתפת: החוגים שלה וביטול עם אישור. מנהלת: כל ההרשמות |
| `/admin` | מנהלת | טבלת חוגים, הוספה ועריכה, משתתפות בחוג, מחיקה, הוספת קטגוריה |

## הרגע החשוב: מקום אחרון ו-409

המשאב המוגבל הוא המקומות בחוג. כשנשאר מקום אחד ושתיים לוחצות "הירשמי" יחד, השרת מאשר רק אחת, והשנייה מקבלת **409 Conflict**.

הלקוח לא מנחש מה קרה לפי נוסח ההודעה. אחרי 409 הוא בודק בשרת מה המצב עכשיו:

1. **היא כבר רשומה לחוג** → "את כבר רשומה לחוג הזה".
2. **החוג התמלא** → הכרטיס רועד, מספר המקומות מתעדכן ל-0, ומופיעה ההודעה "אוף, מישהי הקדימה אותך בשנייה" עם קישור לחוגים שיש בהם מקום.
3. **אחרת** (למשל עומס) → הודעת השרת.

אחרי הרשמה מוצלחת, החוג נטען מחדש מהשרת, כך שהמספרים תמיד אמיתיים ולא "ניחוש" של הלקוח.

**לבדיקה:** חלון רגיל עם לאה וחלון גלישה פרטית עם שרה. שתיהן פותחות את "סריגה ורקמה" (נשאר בו מקום אחד) ולוחצות "הירשמי" בזה אחר זה.

## מבנה הקוד

```
src/
  api/          client.js — fetch אחד לכל האתר: token, תרגום ProblemDetails ל-ApiError, הודעות בעברית
                endpoints.js — כל כתובות השרת במקום אחד
  auth/         AuthContext — התחברות, שמירה בדפדפן, ניתוק אוטומטי כשה-token פג · guards — הגנה על דפים
  hooks/        useForm, usePagedQuery, useDebouncedSearch, usePageParam, usePageTitle
  components/   Layout, Toast, Modal, ConfirmDialog, AsyncList, Pagination, Avatar, Icon, ErrorBoundary
                form/ — Field, PasswordField, FormAlert, SubmitButton
  lib/          format (ימים, תאריכים, מחיר), validation (חוקי טפסים), categoryTheme (צבע לפי Id)
  pages/        auth/, courses/, my/, admin/, NotFoundPage
  styles/       tokens.css (משתני העיצוב) · base · layout · components · עמוד לכל אזור
```

**עקרונות:**
- **בלי כפל קוד.** כל רשימה בנויה מאותם שלושה חלקים: `usePagedQuery` לטעינה, `AsyncList` למצבים ו-`Pagination` לעמודים. כל טופס בנוי מאותם חלקים: `useForm` עם `Field`. גם כל חלון משתמש באותו `Modal`.
- **הלקוח לא סומך על עצמו.** בדיקות הטפסים נותנות משוב מיידי, אבל ההחלטה תמיד של השרת, ושגיאות ממנו מוצגות באותו מקום.
- **צבעי קטגוריות לא נשמרים במסד.** הלקוח גוזר אותם מה-Id מתוך פלטה של 8 גוונים, ולכן קטגוריה חדשה מקבלת צבע אוטומטית.
- **שגיאת שרת (500)** מוצגת עם מזהה הבקשה (Correlation ID), כדי שאפשר יהיה לאתר אותה בלוג של השרת.

## נגישות וטלפון

- HTML סמנטי: כותרת לכל דף, תוויות לכל שדה, ו-`aria-invalid` עם `aria-describedby` לשגיאות.
- קישור "דילוג לתוכן". במעבר דף הפוקוס עובר לתוכן, וכותרת הלשונית מתעדכנת.
- החלונות בנויים על `<dialog>`: הפוקוס נשאר בתוכם ו-Esc סוגר. בחלון אישור הפוקוס מתחיל על "ביטול".
- שורת המושבים מוקראת כטקסט, למשל "2 מתוך 3 מקומות תפוסים". ההודעות הקופצות מוכרזות לקורא מסך.
- פוקוס נראה לעין, וכל האנימציות נעצרות כשמוגדר `prefers-reduced-motion`.
- מותאם לטלפון: תפריט נפתח, כפתורי קטגוריה בגלילה אופקית, וטבלת הניהול הופכת לכרטיסים.

## בנייה ופריסה (Render — Static Site)

```bash
npm run build      # התוצאה בתיקייה dist/
npm run preview    # בדיקה מקומית של הבנייה
```

הגדרות ב-Render:
- **Build Command:** `npm install && npm run build`
- **Publish Directory:** `dist`
- **Environment:** `VITE_API_URL=https://<כתובת-השרת-ב-Render>`
- **Redirects/Rewrites:** `/*` → `/index.html` (Rewrite). זה נדרש כדי שרענון של כתובת כמו `/my` לא יחזיר 404.

אחרי הפריסה צריך להוסיף את כתובת הלקוח למשתנה הסביבה של השרת: `Cors__AllowedOrigins__0`.
